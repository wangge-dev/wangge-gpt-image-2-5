# 来源、版本与复现状态

“Image 2.5 专用”指本库的研究与收录对象明确属于 2.5，不代表所有任务都是 2.5 独有。

## 两个独立维度

| 模型依据 | 表达方式 |
| --- | --- |
| 官方 2.5 章节或示例 | 官方明确标为 2.5；本库是否复现另记 |
| 明确 API 型号 | 记录请求/返回信息及平台，不公开密钥 |
| ChatGPT 界面标识 | 保存可见依据；具体 Flare/Sunburst 未知 |
| 仅作者声称 | 候选区，继续找过程和型号证据 |
| 未知、仅提示词写着 2.5 | 候选区，不计入明确版本案例 |

复现状态只用：未复现、已复现、部分成功、失败、待重新验证。复现者另写“原作者”或“本仓库”，不能互相替代。

## 案例收录

有可追溯的 2.5 依据时可以建立来源案例卡，但必须显示我们的复现状态。作者明确给出 API 型号仍不等于我们独立验证了其后端。
正式卡包括：用途、作者与原文、版本依据、输入/输出入口、提示词性质、已知缺口、核查日期。
原文有图但本轮没有实际看图时，只能报告文字和链接核查，不能写视觉评测。

原创设计放实验区，不伪装成官方推荐或已经成功的模板。原作者提示词、翻译、个人改写、逆向推测分别标明。只有图没有提示词时可以自己设计实验，但不能称“原始提示词”。

## 如何写结果

“这次标题正确”与“中文稳定正确”需要不同证据。完整记录错误、重试、后期处理和限制。
“2.5 比 2 更好”需要可比较的版本实验，单张漂亮图不能支持。
电商图应检查商品信息是否真实；生成的未知商品背面、内部结构、证书、功能说明不作为产品事实。

旧库、微软 MAI-Image-2.5、其他模型的结果不列入本库 2.5 成果。可保留来源链接和比较问题。
未来官方页面可能切换默认版本，核查时先看章节和示例标签，不凭页面标题推断。
