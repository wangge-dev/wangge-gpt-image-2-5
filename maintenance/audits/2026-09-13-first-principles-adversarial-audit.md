# 第一性原理与对抗式审查

日期：2026-09-13  
范围：代码、公开文档、维护文档、数据源、八套电商任务包与仓库 `AGENTS.md`。本轮只读审查，不删除文件，不修正文内容。

## 目标、约束、事实与假设

目标不是单纯增加提示词数量，而是让电商用户提供商品素材后，能找到从主图到详情素材的一套顺序，复制每一步提示词，并在结果偏差时知道如何局部修改。

核心约束：商品结构、数量、包装文字、参数、人物和场景必须来自输入证据；旧版创意适配、明确2.5来源、实际2.5输出和2.5独占能力必须分别表述；未生图不得写成已复现；完整提示词是主要交付；电商入口长期保留；公开页不堆内部维护话语。

当前业务事实：仓库有84张JSON卡（30电商、22模板、32画廊）、11条明确版本来源案例、9条原创实验，总计104条基础提示词，117个完整变体；八套电商品类任务包共48个步骤；3张本库用户结果、29张外部参考图；987个本地Markdown链接检查通过。当前任务包未做统一生图测试。

现有方案依赖三个关键假设：用户商品接近预设示例SKU；用户能提供多角度、细节、场景、参数或说明书；用户能自行把示例事实改成自己的事实。前两个假设在真实新用户场景中经常不成立，第三个假设削弱了“拿来就用”。

## 总体判断

方案已经解决“八个示例商品在资料齐全时，按六步生成并按提示返工”的文档链路；尚未完全解决“任意用户上传自己的商品图后直接获得整套素材提示词”。下一阶段应先把任务包变成一次填写事实、六步复用，并提供单图最小路径，再统一生图测试。继续只增加固定SKU任务包会扩大内容量，但不会解决这个核心缺口。

## 真实问题

### P1 · 固定示例SKU被描述为按品类直接执行

- 证据：`ecommerce/README.md:86-97` 和 `README.en.md:9` 使用“按品类直接执行 / ready-to-copy”；八套任务包第5行固定了精华瓶、白T恤、水饺、床头柜、键盘、加湿器、托特包和训练杯，后续六段继续写死颜色、结构和数量。只有 `ecommerce/kits/beauty.md:65` 明确提示其他商品改用变量模板。
- 触发条件：用户商品与示例SKU不完全一致，这是常态。
- 影响范围：八套任务包全部。直接复制可能把错误颜色、部件、数量或包装带入结果；用户仍需逐段重写。
- 建议：每套增加“一次填写的商品事实单”，六步统一引用；保留当前固定SKU作为填写示例，不把示例正文当成通用品类正文。

### P1 · “上传商品图”与实际素材门槛不一致

- 证据：八套任务包通常要求4至6张多角度、细节、场景、模特或包装图，并要求尺寸、参数表或说明书，例如 `ecommerce/kits/food.md:5`、`ecommerce/kits/baby.md:5`。
- 触发条件：用户只有一张正面商品图。
- 影响范围：48步中的多角度、微距、试穿、空间融入、结构、规格和步骤图。
- 建议：明确“单图最小流程”和“资料齐全完整流程”；逐步标注缺少某项素材时应跳过、降级还是补拍，禁止用模型猜背面和参数。

### P1 · 食品第6步使用未列出的输入

- 证据：`ecommerce/kits/food.md:59` 只要求图2和三张步骤照，`ecommerce/kits/food.md:62` 却要求上方展示图1包装。
- 触发条件：用户按本步材料行上传素材。
- 影响范围：食品烹饪步骤图。
- 建议：将图1加入第6步输入清单。

### P2 · 英文首页范围过期

- 证据：`README.en.md:11` 已写EC01–EC25，`README.en.md:65` 仍写EC01–EC20；`AGENTS.md` 要求中文首页更新时同步英文README。
- 触发条件：英文读者从页面后半段查看最新进度。
- 影响范围：英文公开说明与维护规则一致性。
- 建议：统一为EC01–EC25，并同步八套任务包现状。

### P2 · 数据、图片和待办统计过期

- 证据：`data/README.md:3` 写78张JSON卡，实际84张；`data/README.md:9` 写5条cases，实际11条；`ATTRIBUTIONS.md:20` 写28张外部参考图，实际29张；`discovery/backlog.md:5` 写510条未精选，按541项减32条已选应为509条。
- 触发条件：维护者按说明核对数量或对外引用。
- 影响范围：数据维护、版权说明、候选队列和交接判断。
- 建议：从现状统一修正；后续避免在多处手工维护同一动态数字。

### P2 · 上游追踪入口停在旧提交

- 证据：`maintenance/README.md:29`、`maintenance/update-prompt.md:14` 和 `discovery/sources.md:42` 仍记录原作者核查至 `073d105`；`maintenance/reviews/2026-09-13-source-and-ecommerce-review.md:5` 已核查到 `0dc09c46`，该更新只有赞助内容。
- 触发条件：下一维护者按维护入口开始工作。
- 影响范围：重复扫描、候选判断与核查时间线。
- 建议：把维护入口推进到已验证提交，同时保留来源内容实际引用的旧提交不变。

### P2 · 生成脚本可能留下半生成状态

- 证据：`scripts/build_library.py` 在遍历数据时直接逐文件写入，全部条目尚未验证完成前就开始修改生成文件。
- 触发条件：后部条目缺字段、渲染异常或进程中断。
- 影响范围：已生成卡与未生成卡、索引可能短暂或提交后不一致。
- 建议：先在内存完整渲染并验证所有目标，再统一落盘。当前数据正常，属于可验证的异常恢复缺口；不需要引入复杂发布门禁。

## 其他审查维度

- 安全：没有发现凭据文件或服务端执行入口；静态画廊用 `textContent` 和DOM属性写入内容，JSON中的 `<` 已转义。人物素材要求获准使用，母婴包限制安全信息扩写。无高优先级问题。
- 性能：画廊仅104条、约159KB级JSON，当前一次性筛选和DOM渲染可接受。
- 并发：当前是单维护者静态仓库，没有运行时共享写状态；无需为假设并发增加锁。
- 依赖：构建脚本仅依赖Python标准库，静态页面无构建依赖；依赖风险低。
- 数据一致性：84个JSON ID无重复，生成卡齐全；104个总条目、117个变体与画廊数据一致。本地链接987条通过。
- 文档一致性：公开定位与 `AGENTS.md` 大体一致；上述英文范围、统计和核查提交存在真实偏差。
- 未验证边界：模型成图质量、跨轮商品身份稳定、中文小字、局部返工成功率和实际尝试次数尚无统一测试证据。

## 修复顺序

1. 修复食品第6步输入和过期文档事实。
2. 将八套固定示例改成“事实单＋通用六步”，同时保留示例。
3. 增加单图最小路径与资料齐全路径。
4. 增加轻量语义检查：每套6步、每步来源/输入/正文/验收/返工、正文输入图引用有声明、无未填变量。
5. 完成提示词链路后，按品类统一进行有明确模型记录的生图测试。
