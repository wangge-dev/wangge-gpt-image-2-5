# EC64 · 购买前问答与待确认信息详情卡

[全部提示词](../README.md) · [首页](../../README.md)

**分类：高频电商成片 · 本库原创设计 · 面向 GPT Image 2.5**

把买家已提出的1–3个问题与人工审定答复排成一张详情图，明确哪些已确认、哪些还需补资料，不把未知自动变成卖点。

## 准备材料与变量

图1为当前商品原照，只负责可见外观；文字提供1–3条问题、逐字答复、人工状态与来源。状态只能由人工设为“已确认”或“待确认”；未提供答案就删除该问，不让模型自行作答。没有实测、说明书或政策时可明确写待确认，不从照片推参数。

将下表中的值按实际任务填写，然后复制正文。示例值用于说明填写方式，不是已核实的商品事实。

| 变量 | 填写示例或说明 |
| --- | --- |
| `{{商品}}` | 照片中的白色方桌，只用已拍外观，不推现售型号或参数 |
| `{{标题}}` | 购买前请确认 |
| `{{问答清单}}` | 第1组：问题“图中桌体是什么颜色？”；答复“照片中的桌体为白色。”；状态“已确认”；依据“图1可见外观”。；第2组：问题“能从这张图确认尺寸吗？”；答复“不能；本例没有实测尺寸。”；状态“待确认”；依据“本例未提供尺寸”。；第3组：问题“材质和承重有依据吗？”；答复“本例未提供，购买前需另行确认。”；状态“待确认”；依据“本例未提供对应资料”。 |
| `{{底部说明}}` | 仅演示已知与待确认信息 |

## 拿来就用的具体示例

只上传白色方桌原照 assets/samples/ikea-lack-white-table/source.jpg。照片Juhan Sonin／CC BY 2.0；三条问答是按可见外观和本例未提供资料人工写定的教学文案，不是IKEA现售页面答复、店铺承诺或真实客服记录。

按示例准备对应素材后，直接复制下段；其他商品使用后面的变量模板。

```text
制作一张4:5购买前问答详情卡。图1只负责商品身份和已拍外观：照片中的白色方桌，只用已拍外观，不推现售型号或参数。问答、状态和依据只来自人工清单：
第1组：问题“图中桌体是什么颜色？”；答复“照片中的桌体为白色。”；状态“已确认”；依据“图1可见外观”。
第2组：问题“能从这张图确认尺寸吗？”；答复“不能；本例没有实测尺寸。”；状态“待确认”；依据“本例未提供尺寸”。
第3组：问题“材质和承重有依据吗？”；答复“本例未提供，购买前需另行确认。”；状态“待确认”；依据“本例未提供对应资料”。
模型不自行发现问题、回答问题、判定状态或补来源；答复与证据相反时暂停冲突项请人工核对，不重画商品使其相符。

四周5%安全区；可用高度上10%标题、下接32%完整原照、4%间隔、44%问答区、底10%说明。照片完整等比例适配，不裁断桌腿或商品边缘，不镜像、扩图、补背面或重打光；原照背景可保留在独立照片窗里。问答按清单由上至下排列，1–3组均分问答区，每组问题在上、答复在下，状态放组内右上，不跨组连线；没有的组删除，余下组均分可用区，不留空问号。先读标题，再看商品，再读问答。

标题只写“购买前请确认”，底部只写“仅演示已知与待确认信息”；各一次。每组只排清单引号内的问题、答复和状态，依据字段只供核对不上屏；状态用中性深灰小标签，不画绿色勾、红叉、客服头像或认证章。“待确认”不是“不支持”，也不是默认承诺；不要自动补尺寸、材质、承重、兼容、功效、发货、价格、保修或活动规则。

米白底、深灰字和细分隔线；每个问题最多一行、答复最多两行，保持清楚层级，不改写或省略限定词。放不下时暂停对应组，转人工短文或拆成另一张独立卡，不缩小字、删字或挤进照片。原照像素需精确保留时使用外部图层排版。只输出一张可读详情图，不输出客服对话截图或资料核对板。
```

## 参数设置

建议画布：`1536x1920`；模型选择及格式见[模型说明](../../guides/models.md)。网页版可按相同比例描述画布。

与EC11卖点模块不同，本卡保留买家问题、答复及人工待确认状态，服务购买前的信息理解，不自动把回答包装成好处。照片许可不等于商品资料或品牌背书；输入原照及改编需保留作者、许可和改动说明。


修改前，将修改指令中的双花括号内容按实际问题填写；每次只处理一个位置。
